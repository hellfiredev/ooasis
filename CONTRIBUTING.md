## How Can I Contribute?

### Reporting Bugs

Before creating a bug report, please check existing [GitHub Issues](https://github.com/hellfiredev/ooasis/issues) to avoid duplicates.

If you find a new bug, please open an issue using the [Bug Report Template](.github/ISSUE_TEMPLATE/bug_report.md) and include:
- A clear, descriptive title.
- Steps to reproduce the issue.
- Expected behavior vs. actual behavior.
- VS Code version, OS version, and Ooasis version.
- LLM backend information (e.g., LM Studio, Ollama, API endpoint).
- Relevant console logs or error traces (from VS Code Developer Tools: `Help > Toggle Developer Tools`).

### Suggesting Features & Enhancements

We welcome proposals for new features and improvements! Please open an issue using the [Feature Request Template](.github/ISSUE_TEMPLATE/feature_request.md) explaining:
- The problem or use case you are addressing.
- Your proposed solution or workflow.
- Any alternatives or trade-offs you considered.

### Contributing Code

Feel free to pick up any open issue labeled `help wanted` or `good first issue`, or submit a PR for an agreed-upon feature or bug fix. For large or breaking architectural changes, please open a discussion or issue first to align on approach.

## Project Architecture

Ooasis is split into two interconnected layers:

```
ooasis/
├── src/                # Extension Host (Node.js / VS Code Extension API)
│   ├── extension.ts    # Entrypoint & command registrations
│   ├── config.ts       # Extension configuration & options
│   ├── tools.ts        # Agent tool execution (file ops, terminal)
│   ├── summarizer.ts   # Chat title generation & summarization
│   └── providers/      # WebviewViewProvider implementations
├── webview-ui/         # Frontend Webview (React 19 + Vite)
│   ├── src/            # React components, hooks, markdown/KaTeX renderers
│   └── package.json    # Frontend dependencies and scripts
└── out/                # Bundled extension output (generated by esbuild)
```

The **Extension Host** handles lifecycle events, LLM communications, workspace context reading, and secure agent tool execution. The **Webview UI** renders the interactive chat interface, streaming tokens, thought process/reasoning blocks, and math/markdown snippets, communicating with the host via VS Code's `postMessage` protocol.

## Development Setup

### Prerequisites

- **Node.js**: `v20.x` or later (Node 24 recommended)
- **npm**: `v10.x` or later
- **VS Code**: `v1.136.0` or later
- **Git**

### Installation

Clone the repository and install dependencies for both the root extension and the webview UI:

```bash
# Clone the repository
git clone https://github.com/hellfiredev/ooasis.git
cd ooasis

# Install root extension dependencies
npm install

# Install webview UI dependencies
cd webview-ui
npm install
cd ..
```

### Running the Extension Locally

1. **Start the watcher**:
   ```bash
   npm run watch
   ```
2. **Launch the Extension Development Host**:
   - In VS Code, press `F5` (or navigate to `Run and Debug` in the Activity Bar and click **Run Extension**).
   - A new VS Code window will launch with the Ooasis extension active.
   - Look for the **Ooasis** icon in the Secondary Sidebar (or run the command `Ooasis: Add Selection to Chat`).

### Developing the Webview UI Independently

To rapidly iterate on UI components with Vite hot module replacement (HMR) in your browser:

```bash
cd webview-ui
npm run dev
```

Visit the displayed local URL (typically `http://localhost:5173`) in your browser.

## Testing & Quality Assurance

Before submitting a Pull Request, ensure that all linting, building, and automated tests pass.

### Linting

- **Extension Host**:
  ```bash
  npm run lint
  ```
- **Webview UI**:
  ```bash
  cd webview-ui && npm run lint && cd ..
  ```

### Running Tests

Run the VS Code automated test suite:

```bash
npm test
```

### Packaging Validation

Ensure that the project builds and packages cleanly into a `.vsix` bundle without packaging unintended files:

```bash
npm run compile
npm run package
```

## Security Considerations

Because Ooasis executes agent tools (file reading/writing and terminal commands):

1. **Workspace Path Containment**: Any changes to file-based tools in `src/tools.ts` must maintain strict workspace boundary containment. Absolute paths or paths escaping the root via `..` or symlinks must be rejected.
2. **Workspace Trust**: Ooasis explicitly declares `untrustedWorkspaces.supported = false`. Do not bypass workspace trust safeguards.
3. **Security Vulnerabilities**: If you discover a security vulnerability, please **do not** open a public issue. Instead, report it privately following our [Security Policy](SECURITY.md) via [GitHub Security Advisories](https://github.com/hellfiredev/ooasis/security/advisories) or contact the maintainers directly.

## Pull Request Guidelines

1. **Branch from `main`**: Use descriptive branch names:
   - `feat/feature-name`
   - `fix/bug-description`
   - `docs/documentation-update`
   - `refactor/clean-up-area`
2. **Keep PRs Focused**: Keep changes scoped to a single feature or bug fix. Avoid mixing refactorings with new functionality.
3. **Add Tests**: Whenever adding new features or fixing bugs, include corresponding automated tests where feasible.
4. **Fill out the PR Template**: Complete all sections in our [Pull Request Template](.github/pull_request_template.md).
5. **Clean History**: Rebase against the latest `main` branch before opening your PR.

## Commit Guidelines

We recommend following the [Conventional Commits](https://www.conventionalcommits.org/) specification:

```
<type>(<scope>): <short description>

[optional body]

[optional footer(s)]
```

Common types:
- `feat`: A new feature
- `fix`: A bug fix
- `docs`: Documentation changes
- `refactor`: Code change that neither fixes a bug nor adds a feature
- `test`: Adding or correcting tests
- `chore`: Build tasks, package updates, configuration

*Example:* `fix(tools): enforce workspace root boundary on path resolution`

Thank you for helping make Ooasis awesome! 🚀
